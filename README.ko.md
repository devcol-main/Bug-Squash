# Bug Squash

[![CI](https://github.com/devcol-main/Bug-Squash/actions/workflows/ci.yml/badge.svg)](https://github.com/devcol-main/Bug-Squash/actions/workflows/ci.yml)

[English](README.md) · **한국어**

코드를 쓰는 사람을 위한 두더지잡기입니다. 레트로 터미널의 칸마다 버그가 튀어나옵니다. 숨기 전에 잡고, 멀쩡히 돌아가는 기능은 건드리지 말고, 보드가 커져도 버텨야 합니다. TypeScript, Canvas 2D, WebAudio로 만들었습니다. 게임 엔진도, 외부 CDN도, 오디오 파일도 하나 없습니다. 효과음과 배경음악까지 모두 코드로 합성합니다.

## 플레이 방법

| 입력 | 동작 |
|---|---|
| 칸 탭 / 클릭 | 그 칸에 있는 것을 칩니다 |
| `1 2 3 4` / `Q W E R` / `A S D F` / `Z X C V` | 4x4 보드의 칸 (키보드 위치 그대로) |
| `1 2 3` / `Q W E` / `A S D` | 3x3 보드의 칸 |
| `Space` | 시작 / 다시 하기 |
| `M` | 음소거 |

키는 글자가 아니라 키보드 위의 **물리적 위치**로 판정합니다. 한글 입력기를 켜 둬도, QWERTY가 아닌 배열이어도 같은 자리의 키가 같은 칸입니다. 키를 한 번 누르면 그때부터 각 칸 모서리에 해당 키가 표시됩니다.

### 규칙

- 라이프 **3개**로 시작합니다.
- **버그**는 숨기 전에 잡아야 합니다. 놓치면 라이프가 하나 줄어듭니다.
- **단단한 버그**(더 크고 주황색, 등껍질 두 겹)는 두 번 쳐야 잡힙니다. 한 번 치면 금이 갑니다.
- **골든 버그**는 보너스입니다. +50점(콤보 배율 적용)이고, 라이프가 모자라면 하나 돌려받습니다. 놓쳐도 라이프는 줄지 않지만 콤보는 초기화됩니다.
- **기능**(시안색 톱니)은 정상 동작하는 코드입니다. 치면 라이프가 줄어듭니다.
- **빈 칸**을 쳐도 라이프가 줄어듭니다. 보드 바깥을 누르는 것은 괜찮습니다.
- **45초**가 되면 보드가 3x3에서 4x4로 커집니다.

### 점수

| 대상 | 점수 |
|---|---|
| 버그 | 10 |
| 단단한 버그 | 25 |
| 골든 버그 | 50 |

점수에는 콤보(연속으로 잡은 수)에 따라 배율이 곱해집니다. 5콤보부터 **x2**, 10콤보부터 **x3**, 20콤보부터 **x4**입니다. 버그를 놓치거나(골든 포함), 기능을 치거나, 빈 칸을 치면 콤보가 초기화됩니다. 점수는 줄어들지 않습니다. 실수의 대가는 점수가 아니라 라이프와 콤보입니다.

### 난이도 곡선

난이도는 플레이 시간에 따라 오르고(일시정지한 시간은 빼고 셉니다), 동시에 나오는 수는 보드 크기에도 따릅니다. 모든 값에 하한이나 상한이 있습니다.

| | 시작 | 변화 | 한계 (도달 시점) |
|---|---|---|---|
| 출현 간격 | 1.0초 | 초당 x0.985 | 0.35초 (약 69초) |
| 버그가 떠 있는 시간 | 1.4초 | 초당 −0.012초 | 0.6초 (약 67초) |
| 기능 비율 | 10% | 초당 +0.3%p | 30% (약 67초) |
| 동시에 나오는 수 | 2 | 30초부터 3, 4x4에서 4, 90초부터 5 | |

단단한 버그는 20초부터 나옵니다(버그 중 15%, 떠 있는 시간 1.3배). 골든 버그는 15초부터 나옵니다(출현마다 2%, 한 번에 하나, 떠 있는 시간 0.7배). 수치는 모두 [`src/core/config.ts`](src/core/config.ts)에 있습니다.

## 기획 노트

### 두더지잡기에서 "디버깅"으로

출발점은 한 문장이었습니다. "두더지잡기인데, 두더지가 버그라면?" 그러자 나머지 테마가 저절로 따라왔습니다. 칸은 코드가 돌아가는 슬롯이고, 버그는 잡아야 할 대상이고, **기능**은 절대 건드리면 안 되는 정상 코드입니다. 급하게 핫픽스하다가 멀쩡한 곳을 망가뜨린 경험이 있는 개발자라면 아는 그 긴장감입니다. 그래서 게임 오버 화면도 "죽었습니다"가 아니라 **Build failed**입니다.

### 게임마다 다른 정체성

첫 버전은 형제 게임인 [Stack Up](https://github.com/devcol-main/Arcade-Web)의 화면과 소리를 그대로 썼습니다. 어두운 보라색 네온, 별 배경, 신스 배경음악이었습니다. 동작은 했지만 새 게임이라기보다 스테이지 추가처럼 느껴졌습니다. 그래서 Bug Squash를 **레트로 터미널** 컨셉으로 다시 만들었습니다.

- 거의 검은 배경 위로 희미한 "코드" 줄이 터미널 출력처럼 위로 올라갑니다. 글자가 아니라 막대로 그린 줄이고, 그 위에 스캔라인과 비네팅이 있는 CRT 오버레이를 덮었습니다.
- 칸은 타이틀바가 달린 각진 터미널 창처럼 생겼습니다.
- 색은 UI가 형광 녹색, 버그가 앰버, 단단한 버그가 주황, 골든 버그가 옅은 금색, 기능이 시안, 에러가 빨강입니다.
- 모든 글자는 JetBrains Mono입니다. 버튼은 `[Sound: on]`, 체크박스는 `[x]`처럼 씁니다.
- 연출도 터미널답게 바꿨습니다. 잡힌 버그는 픽셀로 흩어지고, 기능을 치면 화면이 흔들리는 대신 가로로 찢어지는 글리치가 일어납니다. `> SCALING UP_` 문구는 한 글자씩 타이핑되고, 게임 오버는 CRT 전원이 꺼지는 모습입니다.
- 배경음악은 신스 패드 대신 칩튠으로, 효과음은 터미널 소리로 바꿨습니다([오디오](#오디오) 참고).

### 남의 캐릭터를 빌리지 않고 버그 그리기

처음 그린 픽셀 아트 버그는 가로로 넓고 납작하며 양옆에 집게가 있었습니다. 그래서 스페이스 인베이더의 외계인처럼 보였습니다. 의도와도 맞지 않고, 남이 가진 외형이기도 합니다. 그래서 몇 가지 규칙을 정해 **위에서 내려다본 딱정벌레**로 다시 그렸습니다.

- 세로가 가로보다 길다
- 머리는 좁고, 가슴과 배 사이에 허리가 있다
- 다리는 한쪽에 세 개씩, 앞·옆·뒤를 향한다
- 눈처럼 보일 수 있는 구멍이 없다
- 맨 아랫줄이 끊기지 않는다

이 가운데 핵심 규칙(세로가 더 길다, 눈처럼 보이는 구멍이 없다, 맨 아랫줄이 끊기지 않는다)은 테스트가 스프라이트 데이터에서 직접 검사합니다. 나중에 그림을 고치다가 슬쩍 외계인처럼 돌아가는 일을 막기 위해서입니다.

### 색이 없어도 구별되게

버그와 기능은 색만이 아니라 **모양**으로 다릅니다. 하나는 딱정벌레 실루엣이고, 다른 하나는 가운데 구멍이 난 둥근 톱니입니다. 단단한 버그는 조금 더 크고 등껍질이 두 겹이며, 금이 가면 픽셀이 빠집니다. 흑백 화면에서도 플레이할 수 있습니다.

### 더 어렵게, 하지만 공정하게

첫 플레이 가능 버전 뒤에 규칙 두 개를 더했습니다.

- **빈 칸을 치면 라이프가 줄어듭니다.** 이 규칙이 없을 때는 모든 칸을 마구 누르는 것이 최선의 전략이었습니다. 이제는 한 번의 탭에 의미가 있어야 합니다. 유예 시간은 일부러 두지 않았습니다. 버그가 사라지는 순간 그 칸은 빈 칸입니다.
- **키보드로도 플레이할 수 있습니다.** 키보드 왼쪽 영역이 보드에 대응해서, 데스크톱에서는 두 손을 쓸 수 있습니다. 두 키를 함께 누르면 두 번 친 것으로 처리합니다.

공정함을 위한 세부도 있습니다. 보드가 커지는 연출 중의 탭은 실수로 치지 않고 무시합니다. 다른 탭에 갔다가 돌아온 첫 프레임 때문에 라이프를 잃는 일은 없습니다. 게임 오버 직후에는 0.6초 동안 입력을 막아서, 마지막에 다급하게 누른 탭이 결과 화면을 넘겨 버리지 않게 했습니다.

### 접근성

**Reduced motion**은 OS 설정이나 옵션 패널에서 켤 수 있습니다. 켜면 다음과 같이 바뀝니다.

- 화면 글리치, CRT 깜박임, CRT 꺼짐 연출이 꺼집니다.
- 흩어지는 픽셀 수가 절반으로 줄어듭니다.
- `SCALING UP` 문구가 타이핑 없이 바로 나타납니다.
- 보드가 커질 때 칸이 미끄러지는 대신 짧게 교차 페이드됩니다.

흐린 글자는 배경과 약 5.7:1 대비가 나는 색을 쓰고, 가장 작은 글자들(규칙 안내, 키 안내, Build failed)은 10px 아래로 내려가지 않습니다.

## 기술 노트

### 구조

```
src/
  core/     순수 게임 로직 (DOM, Canvas, Audio, 저장소 참조 없음)
  view/     Canvas 렌더링, 스프라이트, 연출, 레이아웃
  audio/    WebAudio 합성과 배경음악 스케줄러
  input/    포인터·키보드 입력, 칸 변환, 진동
  ui/       화면 흐름, HTML HUD와 오버레이, 옵션, 기록
  shared/   리더보드와 플레이어 프로필 (다른 DevCol 게임과 같은 형식)
  main.ts   이것들을 묶는 게임 루프
tests/      Vitest
```

### 결정적인 core

`core/`는 `tap(cell)`과 `update(dt)`를 받아 이벤트 목록을 돌려줍니다. 잡음, 놓침, 기능 탭, 보드 확장, 게임 오버 같은 이벤트입니다. core는 화면이 있다는 사실조차 모릅니다.

난수는 시드를 가진 생성기를 주입받아 씁니다. 그래서 같은 시드에 같은 입력을 넣으면 언제나 같은 게임이 나옵니다. 나중에 데일리 챌린지를 만들 바탕입니다.

큰 시간 간격은 작은 단계로 나눠 처리합니다. 그래서 한 프레임이 길어져도 45초 확장을 건너뛰거나, 버그가 판정 없이 사라지는 일이 없습니다. 화면, 소리, HUD는 모두 같은 이벤트 목록을 보고 반응합니다.

### 렌더링

- **매 프레임 `shadowBlur`를 쓰지 않습니다.** 빛나는 것들(칸, 버그, 글자)은 크기가 바뀔 때 오프스크린 캔버스에 한 번만 그리고, 이후에는 `drawImage`로 복사합니다. 3x3과 4x4 보드용 스프라이트를 따로 만들어 픽셀 아트를 또렷하게 유지하고, 움직이지 않는 스프라이트는 디바이스 픽셀 격자에 맞춥니다.
- **픽셀 아트를 데이터로 둡니다.** 버그와 톱니는 코드 안의 작은 격자입니다. 같은 격자를 그리기, 테스트의 크기 검사, 픽셀 분해 연출(픽셀 하나하나가 입자가 됨)이 함께 씁니다.
- **연출은 풀링합니다.** 입자, 점수 팝업, 플래시는 고정 크기 풀에서 꺼내 쓰고, 게임 루프 안에서는 매 프레임 객체를 만들지 않습니다.
- **CRT 오버레이**의 스캔라인은 디바이스 픽셀 단위로 그리고, 픽셀 비율에 따라 알파를 보정합니다. 그래서 1.5배 화면이 2배 화면보다 어두워지지 않습니다.
- **디바이스 픽셀 비율**은 최대 2로 제한하고, 창을 다른 모니터로 옮기면 다시 감지합니다.

### 오디오

모든 소리는 실행 중에 WebAudio로 만듭니다.

- **배경음악:** A 마이너, 150 BPM의 8마디 칩튠 루프입니다. 진행은 Am–F–C–G로 묻고, Am–F–G–Am으로 답합니다.
  - 리드: `PeriodicWave`로 만든 펄스파입니다. 듀티 12.5%와 25%를 쓰고, 둘의 음량을 맞췄습니다.
  - 베이스는 삼각파이고, 드럼은 노이즈와 피치가 내려가는 킥입니다.
  - 미리 예약하는 스케줄러를 써서 프레임이 끊겨도 박자가 흐트러지지 않습니다.
- **효과음**
  - 잡을 때: 기계식 키보드 클릭과 8비트 블립. 블립은 콤보가 오를수록 음이 올라갑니다.
  - 단단한 버그에 금이 갈 때: 계단식 글리치음
  - 골든 버그: 코인 아르페지오
  - 기능을 쳤을 때: 터미널 에러 벨
  - 게임 오버: 전원이 꺼지는 하강음과 전기 험
- 소리는 브라우저 자동 재생 정책 때문에 첫 입력 이후에 시작하고, 탭을 숨기면 멈춥니다. 배경음악과 효과음의 음량을 따로 조절할 수 있습니다.

### 입력

마우스, 터치, 펜은 Pointer Events 하나로 처리합니다. 포인터마다 `pointerdown` 한 번이 탭 한 번이라서, 두 손가락으로 두 칸을 누르면 두 번 친 것입니다. 화면 좌표를 칸으로 바꾸는 계산은 순수 함수로 분리했고, 디바이스 픽셀 비율, 레터박스, 칸 경계까지 테스트합니다. 키보드는 `KeyboardEvent.code`를 쓰고, 길게 눌러 반복되는 입력과 단축키 조합은 무시하며, 닉네임을 입력하는 동안에는 꺼집니다.

### 저장과 리더보드

모든 저장은 `localStorage`를 `try/catch`로 감싸서 합니다. 저장소가 막힌 환경에서도 게임은 돌아갑니다. devcol.net에서는 Top 10을 공용 온라인 리더보드(`a.devcol.net/lb`, 서버는 [devcol-analytics](https://github.com/devcol-main/devcol-analytics))에서 가져옵니다. 모든 점수는 로컬에도 저장되고, 서버에 닿지 못하면 "Offline" 안내와 함께 로컬 순위를 보여 줍니다. 로그인은 없고, 첫 제출 때 받은 랜덤 토큰(`devcol.player.token`)으로 Options → Online scores → Delete mine을 할 수 있습니다. 플레이어 ID는 보내지 않으며, 부적절한 이름은 `Player####`로 보입니다. devcol.net 밖에서는 로컬 전용입니다(`npm run dev`에 `?lb=http://localhost:8787/lb`를 붙이면 로컬 Worker에 연결). 모두 `LeaderboardService` 인터페이스 뒤에 있습니다. DevCol 게임은 각자 자기 리더보드와 기록을 갖습니다. Bug Squash는 잡은 버그 수, 최대 콤보, 생존 시간을 남깁니다. 작은 공통 플레이어 프로필(아이디 하나와 닉네임 하나)은 따로 두었는데, 앞으로 여러 게임의 순위를 모아 보여 줄 대시보드를 위한 것입니다.

### 크기

프로덕션 빌드는 폰트와 로고를 포함해 약 **164 KB**이고(오디오 파일 없음), CI에서 300 KB 한도를 검사합니다.

## 만든 과정

Bug Squash는 명세를 먼저 쓰고 작은 에이전트 파이프라인으로 개발했습니다([`CLAUDE.md`](CLAUDE.md), [`docs/`](docs/) 참고).

1. 모든 변경은 [`docs/tasks/`](docs/tasks/)의 명세에서 시작합니다. 명세에는 자동 검사와 사람 확인 항목이 체크리스트로 들어 있습니다.
2. 작업은 정해진 순서의 하위 작업으로 나눕니다. core 로직과 테스트, 렌더링, 연출과 오디오, UI, 마무리 순입니다.
3. 하위 작업마다 구현 에이전트가 코드를 쓰고, 검사 에이전트가 타입 검사와 테스트를 돌리고, 리뷰 에이전트가 명세에 비추어 변경을 검토합니다. 반려되면 지적 사항을 붙여 다시 구현합니다.
4. 반복에는 한도가 있습니다. 하위 작업 하나당 세 번까지 시도하고, 넘으면 멈추고 사람에게 묻습니다. 모든 하위 작업은 시도 횟수와 반려 사유까지 실수를 포함해 [`docs/pipeline-log.md`](docs/pipeline-log.md)에 남깁니다.
5. 조작감, 소리의 균형, 실제 기기처럼 테스트로 확인할 수 없는 항목은 작업이 끝날 때마다 사람이 확인할 목록으로 따로 정리합니다.

그 결과 **자동 테스트 487개**가 게임 규칙, 난이도 곡선, 입력 변환, 레이아웃, 연출 상태, 오디오 스케줄링, 저장, 그리고 이 미디어 도구까지 검사합니다. CI는 `main` 대상 PR마다 타입 검사, 테스트, 프로덕션 빌드, 번들 검사를 돌립니다.

## 개발

Node.js 24가 필요합니다([`.nvmrc`](.nvmrc) 참고).

```bash
npm ci
npm run dev      # 개발 서버
npm run check    # tsc --noEmit + Vitest
npm run build    # dist/로 프로덕션 빌드 (상대 경로)
npm run media    # docs/media 다시 만들기 (Google Chrome과 ffmpeg 필요)
```

빌드 뒤에는 `bash scripts/verify-build.sh`로 번들을 검사합니다. 크기 한도 300 KB를 넘지 않는지, 번들에 개발 전용 훅이 없는지 확인합니다.

### 사이트에 넣기

```bash
npm run build
bash scripts/copy-to-site.sh
```

`dist/`를 `../devcol-site/devcol-build/docs/public/games/bug-squash/`로 복사합니다. VitePress 페이지가 이를 iframe으로 띄웁니다.

### CI

[`.github/workflows/ci.yml`](.github/workflows/ci.yml)이 `main` 대상 PR과 푸시에서 `npm ci`, `npm run check`, `npm run build`, `scripts/verify-build.sh`를 차례로 실행합니다.
